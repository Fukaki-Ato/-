# 07 测试与验收标准

## 1. 测试策略

| 层级 | 方式 | 覆盖 |
| --- | --- | --- |
| 核心逻辑 | Vitest 单元测试（Node） | 框架、经济、任务、活动、结算等全部 core 代码 |
| 类型 | `npm run typecheck:core` / `typecheck:cc` | core 纯净性 + ui 与 cc API 类型正确 |
| UI 行为 | 编辑器冒烟（人工） | 各面板交互与视觉，按 docs/04 手测清单 |
| 真机 | 微信开发者工具 + 真机预览（S10） | 登录、广告、分享、云、支付、性能 |

**强制规则**：

- 涉及 core 的会话必须新增/更新对应测试，行覆盖不作为硬指标，但关键分支（失败、边界、幂等、跨天）必须覆盖。
- 会话提交前 `npm run check` 必须全绿；ui 会话至少 `typecheck:cc` 通过。
- 修复 bug 必须附回归测试（core）或报告中的复现步骤（ui）。

## 3. 端到端验收场景（M4 终验收）

1. **新用户首启**：隐私→游客/微信登录→主界面（货币 0/0）→ 开始一局 → 结算领奖 → 主界面货币增加。
2. **经济闭环**：商店购买（货币扣减、道具入包、限购计数）→ 仓库使用 → 角色解锁升级 → 属性生效数据流（传给玩法参数）。
3. **成长闭环**：跑 3 局 → 每日任务可领取 → 一键领取 → 红点消失 → 跨天（改时间）任务重置。
4. **福利闭环**：签到 1 天 → 跨天签到 → 第 7 天循环；每日免费广告奖励。
5. **运营闭环**：活动进度随跑酷推进 → 里程碑领取；排行榜提交与展示（本地/云）。
6. **异常路径**：断网启动、广告取消、配置损坏、存档损坏、快速连点领取、跨天临界点操作。
7. **平台合规**：隐私未同意不登录；iOS 无充值入口；分享可用。
