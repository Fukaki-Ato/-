## 0. 一句话概念

活火山的炉腔内壁。你不是在露天奔跑——你在一条架在岩浆海之上的锻炉运输堤道上狂奔，岩浆随「炉心的心跳」周期性涨落：涨潮漫上堤道边缘、火星溅上路面，退潮露出黑色渣滩与焰髓晶。每 288m 一次喷发，喷发前一秒整座火山先亮起红光——**山在数拍子，你必须跟拍子跑。**

气质三词：**灼热、压迫、停摆的工业巨兽。**

## 1. 世界观

### 1.1 文明：煅火匠（The Emberwrights）
- 他们不崇拜火山——他们**操作**火山。煅火匠在火山颈内壁锚定铜链与卡箍网络，把整座活火山当作一座炉：岩浆是炉液，潮汐是供料节奏，火山颈是烟囱。
- 堤道不是观景道，是**铸运线**：渣斗车沿轨道把熔渣运往炉壁的浇口，班次按潮汐排——涨潮取料、退潮清渣。玄武岩柱阵一半是天然柱状节理，一半是煅火匠**切平加载**过的承重柱（切缝笔直、箍着双瓣铜卡环，与天然柱一眼可辨）。
- 镇炉之宝是「哑阀」（the Dumb Valve）：一只两层楼高的青铜总阀，用来压住火山的喷发冲动，把喷发周期人为拖长，好让炉班组连轴运转。 shift schedule（班次表）就刻在堤道沿线的石碑上——**碑上刻的周期数字，就是今天玩家脚下岩浆的涨落周期**。

### 1.2 陨落：回火之夜（The Backdraft）
- 哑阀压得太久。压力在炉腔深处积蓄到阀体再也吃不消的那一夜，山用一场不停的喷发作答：铜卡箍网络成片熔垂、斗车轨道熔弯、炉班组一夜清空。喷发停了之后，山没有死——**它继续按煅火匠教给它的班次涨落**，一座没人接班也照常换班的钟。
- 证据链（场景里要能读出来，全部落到 §4 资产的损毁态上）：
  1. 卡箍双瓣环大量熔垂（铜的下缘拉出泪滴状垂瘤），只有高处少数还端正；
  2. 哑阀阀轮半熔，轮辐向热源方向弯倒——所有弯倒方向一致；
  3. 班次石碑最后一行刻痕是未完成的（当日班次没刻完人就走了）；
  4. 斗车脱轨姿态全部朝同一侧（回火之夜的气浪方向）；
  5. 锻像（工头像）的手指全部指向炉心深处——不是致敬，是出事那晚的指向。

### 1.3 玩家身份：拾烬者（Embergleaner）
- 山的余温让「焰髓晶」在退潮后的渣滩与岩壁上凝结——地表世界隔绝灰烬线以上的能源就靠它。玩家是敢于在两个喷发窗口之间跑进炉腔抢收晶体的拾烬者：**跟着潮汐的节拍跑，涨潮赶路（岩浆替你清场）、退潮收割（渣滩全线敞开）**。
- 对应现有玩法层：金币/拾取 = 焰髓晶（叙事包装，不改判定）；运行 = 沿铸运堤道的收晶路线。
- 叙事只需氛围支撑，不需要过场：开场镜头从岩浆面低位仰拍 → 涨潮漫过镜头下缘 → 拉起见堤道与远处炉心第一次心跳。

### 1.4 节拍器设定：潮汐即班次表（本场景的世界观核心）
- 潮汐周期 144m（见 §3.1）不是自然现象，是班次表的机械遗产——石碑刻着它，哑阀指着它，炉心的心跳驱动它。玩家读到的一切周期物（石碑、阀、心跳、涨落）必须**同相位**，这是「世界仍在按死者的表运转」这一叙事的物理证据。

## 2. 调色板（7 色，禁止出圈）

| 色 | Hex | 用途 |
|---|---|---|
| 玄武黑 | `#1E1713` | 最暗部：岩壁深处、洞顶天空、雾底色（暖黑，不是纯黑） |
| 熔渣褐 | `#4A3A2E` | 岩壁中间调、雾色、阴影调、渣滩 |
| 浮石灰 | `#B8A99A` | 浮石亮面、灰烬、远雾高光、石碑刻痕底 |
| 烧结赤 | `#7A3B2D` | 火烧氧化岩缘、热熏变面——**热但死**（Lambert 不发光） |
| 哑青铜 | `#6E5B3A` | 锻炉会全部铸件：卡箍、阀、链、轨道、斗车 |
| 炉火橙 | `#FF5A1F` | **唯一发光色**：岩浆、焰髓晶、火星、预警红光、喷柱 |
| 硫壳黄 | `#D9B545` | 硫磺结壳、火鹱翼纹（Lambert 固有色，不发光） |

规则（与 stormspire/palette.ts:1-5 同款纪律）：
- 发光物只用炉火橙一种（`MeshBasicMaterial` 直出，postfx bloom 阈值 0.82 只捞得到它）；
- 「热但死」（烧结赤）与「活火」（炉火橙）严格二分：不发光的热痕迹一律烧结赤；
- 零纯黑（最暗玄武黑）、零默认灰（灰调走浮石灰/熔渣褐）；
- 派生色允许在 7 色内插值（如熔渣褐×炉火橙的烬色），不得引入新色相。

## 3. 地形系统

### 3.1 岩浆潮汐（场景节拍器——本场景的核心系统）

**定义（纯函数，Phase A 渲染层用、Phase B 同公式进 sim，见 §12 矛盾 1）：**

```
周期 P = 144m（玩家 12~26 m/s 下 ≈ 5.5~12.0s 一循环，config/game.json runner.baseSpeed/maxSpeed）
相位 u = dist mod 144：
  u ∈ [0, 40)    低潮驻留   level 0（岩浆面在堤道缘下 6.5m）
  u ∈ [40, 72)   涨潮       level = smoothstep((u−40)/32)   （6.5m → 0.8m，涨率 5.7m/32m）
  u ∈ [72, 108)  高潮驻留   level 1（岩浆面在堤道缘下 0.8m，火星溅上路缘）
  u ∈ [108, 144) 落潮       level = 1 − smoothstep((u−108)/36)（退潮开路，渣滩渐次出露）
```

**喷发（surge）**：`k = floor(dist/144)`，**k 为奇数**的高潮驻留段升级为喷发段——
喷发段窗口：216–252m、504–540m、792–828m、1080–1116m……（每 288m 一次，三幕各摊一次，见 §8）。
喷发段表现：岩浆面 +0.3m 脉动（2Hz）、喷柱 ×3 打在侧柱区（不打赛道，Phase A 不判负）、全场闪橙一次（峰值与衰减复用 `lightning.ts` 的 FLASH_PEAK/0.26s 口径）、灰烬密度 ×2.5。

**1 秒红光预警（种子硬需求）**：喷发段起点 S 前 1.0s 进入预警窗（`dist ∈ [S − v·1.0, S)`，v = 渲染层估速 move/dt，窗宽 12~26m）：
雾色/背景色向炉火橙 lerp（峰值 0.4）、keyLight 色温向暖偏、火星泡速率 ×3、岩浆海自发光抬 30%。
预警必须**可读且提前量恒定**——难度提升不改预警时长（1.0s 是安全底线），难度只走 obstacles.json 现有 difficultyCurve 档位。

**取数口径**：潮位由 `dist` 驱动——侧景模块用 `update(move,t)` 逐帧累积 `distAcc += move`（move 是 runnerScene 传入的插值距离增量，sceneryProps.ts:1-3 头注口径）；喷发特效模块走 `LightningFx.update(dt, dist)` 直接拿 dist（lightning.ts:50 接口签名）。两处算同一个公式，Phase B 收敛到 sim 单源。

### 3.2 堤道配方（三车道读法）
- 路面：玄武黑大板，板缝 0.15m 露熔渣褐；缝内嵌**烧结赤**热裂纹（不发光）；路缘两侧各一条 0.4m 哑青铜镶边条（铸运线的轨基），锈蚀断续。
- 两侧：堤道缘外是 1.2m 宽的**熔渣肩台**（熔渣褐），再外即岩浆海。高潮驻留时岩浆拍上肩台（视觉），低潮时肩台下露渣滩（§3.3 原型 3）。
- 路面水洼→**熔渣反光**：复用 stormspire/roadTex.ts 的 roughnessMap 口径（roadTex.ts:28-69，128² DataTexture、中线干燥带、repeat 4 块/240m），洼改「熔渣油亮带」锁路缘带。
- 假弯道：forgeheartProps.update 调 `setWorldBend(t)`（worldBend.ts:102-105；uniforms 模块级全局，`std()` 工厂已给全部侧景材质注入，sceneryProps.ts:36-40；直建 Basic 件需抄 stormspireProps.ts:56-63 的兜底 traverse）。曲线：`uBendX = 4·sin(t·0.06)`（呼吸横弯，慢于雷脊 0.071）、`uBendY = 3·tideLevel(distAcc)`——**涨潮时远方赛道上抬 3m，整条路读作随潮爬升**（纯视觉）。

### 3.3 地形十原型（30+ 段 = 以下原型的混合编排，不允许出现「素堤道」）
1. **炉口直道（起跑段位，LOOP 0~40m）**：低潮驻留起跑，石碑列队，视线尽头炉心第一次心跳。
2. **蜂巢柱阵段（×8）**：两侧六棱玄武柱簇（§4.2），柱基没入岩浆；高潮时柱群读作「从火里长出来的脚手架」，低潮时柱基环礁出露。低路渣滩在此原型最宽（4~6m）。
3. **渣滩浅台段（×6）**：低路原型——退潮后出露的黑色渣滩（熔渣褐+烧结赤裂纹），滩上凝焰髓晶簇（§4.9）；涨潮时整滩没入，只余肩台。Phase A 纯视觉（无金币生成，见 §12 矛盾 1）。
4. **铸运线段（×5）**：沿堤道一侧铺轨（枕木+双轨，哑青铜），脱轨斗车残阵（§4.11）；vehicle 障碍集中出现段。
5. **断链吊桥段（×4）**：堤道断口由青铜吊链桥接（§4.6），链上挂缺板。
6. **烟囱竖井段（×4）**：岩壁侧悬着石砌烟囱群（§4.7），预警窗内集体喷灰。
7. **熔岩跌水段（×3）**：岩壁破口处熔岩瀑（宽 3~6m 的炉火橙丝带，UV 滚动，对标 stormspire 瀑布丝带配方），落点岩浆面隆包 + 常驻火星迸溅。
8. **铸件坟场段（×3）**：渣滩阶地上散落废弃坩埚（1.2~2m 青铜锅，破口朝向一致）、断锤、弯轨；高价值低路。
9. **晶簇温床段（×3）**：岩壁大面积焰髓晶床（§4.9 的壁挂变体），叙事上「丰收区」，远景最亮处。
10. **哑阀厅段（每圈 ×1，签名段）**：固定 **LOOP 210m 段位**（首圈 Act 1 内 210m 照面，450m 是第二圈复现同一枚——铸运线本就是环线，见 §8 诚实说明），嵌壁哑阀本体（§4.4）+ 厅段前后各一座锻像；喷发预警时阀门缝隙透光。

### 3.4 火山颈内壁（场景的「天空」）
- 内壁 = 一根**管轴 = 路轴（z 向）**的开口大圆管：半径 30m（**腔内径 60m**——§4.1 炉心的几何上限）、长约 260m 盖满视程，`side: BackSide`，玄武黑主体 + 熔渣褐斑纹 DataTexture。管壁沿 z 均匀，运动感由纹理滚动承担（不需逐段回收），远端由雾消隐（线性雾 FOG_NEAR/FAR = 22/120，runnerScene.ts:63）。
- 壁上盘旋**螺旋壁架**（服务栈道遗存）：宽 1.5m 的石条带沿壁螺旋上升，螺距 12m，共可见 4~5 圈；实例化石条 + 每 18m 一根残柱。它是「垂直火山颈内壁盘旋爬升段」的视觉载体——Phase A 与 worldBend 的 uBendY 配合读作爬升（§3.2），真爬升在 Phase B（§13）。
- 壁面倾角读法：壁架螺旋方向与堤道前进向一致（右旋），转向盘旋段的读法靠 worldBend 横弯 + 壁架透视收敛完成。

### 3.5 岩浆海
- 两层异速滚动大平面（抄 atmosphere.ts:52-82 的云海条配方：38m 宽条带、DataTexture 噪声斑、y 0.06/0.12 双层），色熔渣褐底 + 炉火橙亮斑层（亮斑层 opacity 随潮位 0.42→0.7）。
- **潮位驱动**：两层平面 y = −6.5 + 5.7·level（+ 喷发段 0.3·sin(2Hz) 脉动）。低潮时层下补一块「渣滩壳」平面（熔渣褐，随潮位出没）。
- 岩浆面碎裂感：亮斑层的斑纹 UV 以 0.5 倍速反向滚动（壳层漂移错觉），落点火星泡（§6）负责近景活性。

## 4. 建筑资产目录（每件 = 数量地板 / 形制 / 材质 / 损毁态 / 动效 / 玩法功能）

### 4.1 炉心（the Forgeheart）×2（沿 LOOP 错位循环）—— 场景主地标
- **几何校核（先读）**：§3.4 内壁是半径 30m 的圆管（腔内径 60m），炉心必须装进管腔——球冠可见部 **40m 宽 / 冠高 17m**、环轨 **Ø52m** 斜置，均 < 60 ✓。初稿「60~90m 球冠 + Ø100m 环轨」装不进腔，作废；不虚标尺寸（避免重演雷脊 brief 300m→实码 58m 的缩水，tower.ts:26）。
- **形制**：腔底远端的熔融巨核——40m 宽半球冠坐进岩浆海（冠底 y=−10 没入潮面下、冠顶 y≈+7，路轴上方），表面 5~7 条熔流沟壑（炉火橙亮带）；冠上斜跨煅火匠锚架剪影：Ø52m 青铜环轨（环面倾 12°、环心 y=+2）+ 8 条放射断臂（3 条熔断下折）。
- **布置**：×2 沿 LOOP 错位（z=−80 与 −200，x=0 路轴上，仿 tower.ts:21-24 错 z 手法）；相机 z≈9.2，z=−80 处物距 ~89m。
- **可见窗校核**：线性雾 FOG_NEAR/FAR = 22/120（runnerScene.ts:63）、camera far 160（runnerScene.ts:90）——89m 处雾因子 ≈0.68，读作「雾中一团深橙光晕」；发光核 Basic 材质 fog 保持开启（透雾衰减即「炉膛在雾底烧」），心跳快层幅度因此给 ±25%（雾后仍可辨）；z=−200 一枚超雾程与 far 160，随回收推进渐次入画（tower 同款生命周期）。
- **材质**：炉火橙 Basic 发光核 + 玄武黑壳层；锚架哑青铜 Lambert 剪影。
- **损毁态**：环轨断口参差；断臂末端挂着凝固熔滴（泪滴锥）。
- **动效**：心跳 = 发光强度 2 层正弦（快层 0.22Hz 幅 ±25% + 慢层随潮位 0→1 抬 30%）；涨潮时核面熔流沟壑亮度抬升。**每 144m 必被玩家注意到一次**（潮汐牵动，§5.3）。
- **玩法功能**：Act 3 的终景与「炉心回响」尾声的声光源头（闩锁承载见 §8 诚实说明）；全程雾中剪影在场（对标云渊鲸的「巨物必现」条款）。

### 4.2 蜂巢玄武柱 ×60+（实例化）
- **形制**：六棱柱，径 1.2~2.4m，高 6~18m；天然柱=断口参差，锻火柱=顶面切平 + 箍双瓣铜卡环（§4.3）。
- **材质**：玄武黑 Lambert + 熔渣褐 instanceColor 微差（tint 口径，sceneryProps.ts:83-86）；水线以下一段烧结赤热熏带（高度随潮位实时重写，实例矩阵零分配改写）。
- **损毁四态混编**：完好全高 40% / 半高断柱（4~8m，断口暗盖）25% / 崩尖柱（顶部 1/3 斜切）20% / 倾倒柱（15° 斜插渣滩，可读作斜坡）15%。
- **动效**：无自主动效（InstancedMesh 静态）——潮位热熏带逐帧重写是唯一动态。
- **玩法功能**：侧景压迫 + 群飞穿柱路径（§5.1 参数化群飞，硬指标：路径至少 2 次穿柱缝）；倒柱是「柱阵坍塌」障碍皮（§9 obs_adwall）的原型。

### 4.3 铜卡箍环 ×12
- **形制**：双瓣青铜环，内径 1.6~2.6m（抱柱），瓣间高强螺栓耳 4 枚；环厚 0.12m。
- **材质**：哑青铜 Lambert；内缘一圈烧结赤热痕。
- **损毁态**：7 只端正，5 只熔垂——下瓣拉长 20~35% 呈泪滴垂瘤（回火之夜证据 1）。
- **动效**：涨潮段热胀微颤（scale 1±0.8%，1.5Hz，只在 level>0.6 时激活）。

## 7. 光照与后期

### 7.1 themes.json 光照字段（runTheme.ts:57-65 消费）
```json
"lighting": { "hemiSky": "#B8A99A", "hemiGround": "#5A2E1C", "hemiIntensity": 1.0, "key": "#FFD2A8", "keyIntensity": 1.1 }
```
- hemiGround 取熔渣褐×炉火橙的暖反照（岩浆海贴身反光）；keyLight 暖白偏橙（炉腔漫射日光位）。
- 闪白增益沿用 FLASH_LIGHT_GAIN 2.6（lightning.ts:27）——喷发时全场过曝一拍，正是「炉膛开盖」的读法。

### 7.2 天空 / 雾 / 地面（themes.json）
```json
"sky":  { "shader": "thunder_sky", "baseColor": "#1E1713", "flashColor": "#FF8A50", "flashEveryS": [9999, 9999] },
"fog":  { "color": "#4A3226", "density": 0.013 },
"groundColor": "#2A201A"
```
- `flashEveryS [9999,9999]` = **关闭**环境闪电（洞内无天雷）；喷发改由 §6 的 eruption 管线驱动（§12 矛盾 2）。
- ⚠️ 事实核对：`sky.flashColor` 的运行时消费方是 trackVisuals 护栏加色材质（trackVisuals.ts:223），**闪电/闪白色不读它**——闪白色是 lightning.ts:25 的常量 FLASH_TINT（runTheme.ts:67 落地）。forgeheart 的暖闪必须走 flashTint 值分支（§12 矛盾 2 方案 B 的一部分），不是配 flashColor 就生效。
- ⚠️ 事实核对：`fog.density` 是**死配置**——runTheme.ts:52 只读 fog.color，runnerScene.ts:88 建线性 `Fog(color, FOG_NEAR=22, FOG_FAR=120)`（:63 常量），density 无任何运行时消费方（全 packages/game/src 零命中）。仍按 0.013 填（对未来 FogExp2 接线无害），炉腔包容感由 §6 热浪雾带 + 雾色承担；density→FogExp2 接线列 §13 Phase B。雾色熔渣褐近暖——炉心方向的「透橙」由炉心本体发光与灰烬承担，不加第二层体积雾（postfx 避雷清单：无强体积光）。

### 7.3 后处理链（render/postfx.ts 现成）
- 直接复用：RenderPass → UnrealBloom(0.32/0.35/0.82) → grade → OutputPass（bloom 三常量 postfx.ts:21），wx 自动降级门不变（postfx.ts:9-13）。冲刺联动曲线沿用现有数值：暗角→0.42、饱和→0.86、bloom→0.50（postfx.ts:23-25 常量）。

## 8. 赛道叙事（三幕 + 潮汐绑定 + chunk 池）

> 现有玩法是 lane + worldZ 平面滚动赛道（segmentLengthM = 24，trackGen.ts:79）。Phase A 赛道保持三车道平面；「内壁盘旋」「低路渣滩」全靠视觉层（§3.2 worldBend + §3.3 原型）。潮汐与喷发在 Phase A **不判负**。

### Phase A 诚实说明：签名件与 240m 循环（先读本节再读三幕）
- 侧景全部走 LOOP=240 无条件循环回收（sceneryProps.ts:20-21 与 186-198 的逐帧回收循环；SceneryProps.update 只收 move/t，sceneryProps.ts:156）——**渲染层没有绝对距离上的编排能力**。brief 里所有「×1」「450m 附近」「尾声」一律读作「**每圈该段位复现**」：哑阀厅固定 LOOP 210m 段位（首圈 Act 1 内 210m 照面，450m 是第二圈复现同一枚），炉心、锻像、熔岩跌水同理沿 LOOP 各就其位、每圈照面——铸运线本就是环线，复现在叙事上自洽。
- 「炉心回响」「按圈变奏」类一次性/渐变事件由**距离闩锁状态机**承载：侧景模块自累计 dist（§3.1 的 distAcc 口径）驱动状态 = f(圈数/距离阈值)，首次经过尾声段位触发加码 burst、此后每圈按状态变奏——渲染层确定性、不回写 sim（同 titan-brief.md:103 睁眼闩锁的实现口径与 titan-brief.md:228 的诚实说明先例）。
- 喷发节奏（每 288m，§3.1）本身是 dist 纯函数、天然跨圈成立，不依赖闩锁；闩锁只承载「一次性与渐变」叙事（尾声 surge 加码、炉心心跳随圈渐频）。

### Act 1 — 炉喉栈道（0~240m = 10 段；含第一个完整潮汐周期 + 第一次喷发）
- 0~40m 低潮驻留起跑：班次石碑列队引路（§4.10），障碍温柔——熔渣矮垣、第一道卡箍残梁（滑铲）。
- 40~72m 第一次涨潮：玩家看岩浆漫上肩台、熔岩蜥钻缝（教学：**潮涨路窄，走中线**）；72~108m 高潮驻留，路缘火星溅起、渣滩没顶——第一次「高压拍」。
- 108~144m 落潮开路：渣滩出露、焰髓晶最亮、石碑刻痕开始可读。
- 216~252m **第一次喷发**：阀亮 → 一秒红光 → 三根喷柱 → 全场闪橙（种子「每次喷发前一秒全场景红光预警」的第一次兑现）。喷发窗尾部 240~252m 跨入 Act 2 首段——chunk 池把该 0.5 段并入 Act 1 权重，叙事上作 Act 1 收尾。结束时回头能望到哑阀厅（本圈 210m 段位）的轮廓。

### Act 2 — 蜂巢柱海（240~600m = 15 段；两个半潮汐周期）

## 12. 与代码库事实的矛盾与两方案（动手前必读）

### 矛盾 1：「涨潮封低路、退潮开新路」vs sim 出生即定的安全道保底
- **事实**：patterns 的 `guarantee.safeLanePattern` 在障碍出生时已锁定安全道（obstacles.json patterns 全表），laneBlock 权重也是出生时按档抽取；运行时按潮汐动态封道会在高潮驻留段封掉已保底的安全道，破坏「必有活路」与 near-miss 计分前提。且 sim 无潮汐概念，潮位目前只是渲染层纯函数。
- **方案 A（推荐，Phase B）**：**出生时潮汐感知放置**——tide(dist) 是纯函数，trackGen 在出生时刻就能算出玩家到达该 cell 时的潮位：低潮窗排渣滩金币线/低路呼吸 pattern，高潮窗排封路密度 pattern。零运行时冲突、回放安全（同为 dist 纯函数）、不碰 guarantee 语义。
- **方案 B（不推荐）**：运行时掩道——sim 每步按 tide(dist) 屏蔽侧车道输入/判负。与 safeLanePattern 保底直接冲突，需要新的保底合成规则，回放与 golden 路径全要重验。仅当方案 A 的「提前量」被证伪（玩家变速导致到达潮位与出生预估漂移）才回退到 B——但潮汐周期 144m ≫ 变速窗口，漂移上限 < 半个相位，实际不成立。
- **Phase A 处置**：潮汐纯视觉（§3.1 已声明），低路渣滩无金币、封路全由 pattern 池承担，两方案都留给 Phase B。

### 矛盾 2：「喷发前一秒红光预警」vs 现成环境闪电（随机、无预告、天→地）
- **事实**：现有环境闪电由 runnerScene 的渲染层随机定时器触发（runnerScene.ts:196-199，flashGap 来自 themes.json `flashEveryS`），`lightning.strike` 是瞬时召唤、无预告窗；视觉是「天→地劈雷」（lightning.ts:94-116，SKY_Y=22 顶点入画）。另 runnerScene.ts:201-206 **每帧无条件**用 applyLightningFlash 覆写背景/雾色（flash=0 时也是精确覆写）——侧景模块若自包含写 scene.background 会被同帧覆写，**预警红光无法由 forgeheartProps 自包含实现**。
- **方案 A（零代码兜底）**：`flashEveryS: [11,17]` 直接复用随机雷击。零改动，但视觉是「洞顶劈雷」且**无法实现 1s 预警**（随机触发无预告）——种子核心需求不达标，只当契约冒烟的临时档。
- **方案 B（推荐，~180 行）**：新建 `forgeheart/eruption.ts` 实现 LightningFx 同款接口（strike(lane,worldZ,laneWidth) / update(dt,dist)→flash / dispose，lightning.ts:46-53）：内部按 §3.1 纯函数自行排程喷发与预警窗，返回 flash 强度；几何反向（喷柱地→天 + 频闪断口），池化 3 槽。runnerScene 两处显式分支（各 1~3 行，沿用 runnerScene.ts:100 环境贴图门控与 entityLayers.ts:64 皮肤门控的 scenery 分支惯例）：① 环境触发器 forgeheart 时跳过 ambientT 随机、由 eruption.update 自驱（返回值仍走 :202-206 现有灯光/雾/背景管线）；② flashTint 按 scenery 取暖色常量 `FORGE_TINT #FF8A50`（applyLightningFlash 的 tint 本就是入参）。zap 事件（runnerScene.ts:162-165）与死亡雷击自动继承喷柱视觉。

### 矛盾 3（小，配置陷阱）：themes.json 的 `sky.flashColor` 不是闪白色
- **事实**：flashColor 的运行时消费方只有 trackVisuals 护栏加色材质（trackVisuals.ts:223）；闪白/闪橙色走 lightning.ts:25 常量 + runTheme.ts:67 固化。**配 flashColor 不会改变喷发闪色**。处置：flashColor 仍配 `#FF8A50`（护栏语义正确），闪色走 §矛盾 2 方案 B 的 tint 分支。
