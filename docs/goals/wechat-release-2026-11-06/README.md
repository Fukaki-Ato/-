## 关键判断

1. **当前是小游戏路线。** `apps/wx/project.config.json` 的 `compileType` 为 `game`。微信官方将小游戏定义为小程序的一个类目，因此这条路线符合通常所说的“微信小程序游戏”。如果用户明确指普通 WXML 小程序，需要先讨论运行时差异，不能简单改配置冒充完成迁移。
2. **先让目标平台跑通，再做大规模美术落地。** 当前 WX 启动的是空场景；Web 的 DOM 大厅和任务页不能直接搬到小游戏里运行。
3. **先统一权威数据，再完善福利与消费。** 目前跑局金币、任务钱包和本地档案分属不同链路。只加一个漂亮领奖页会留下“已领取但不能消费”的断点。
4. **继承氛围，允许重做表达。** 推荐保留晴日海滨、暖沙、清透蓝与轻快跑酷感；布局、材质、场景组织方式均可重设计。旧文档中“此次只改 UI、不改跑酷场景”的历史范围，不限制本次新目标。
5. **当前不存在已建好的 Cocos 工程。** 历史架构文档的 Cocos 方向是候选路线，不是本次必须迁移引擎的用户要求。先评估现有 Three.js/WX 适配能否达标，用目标端结果决定。

## 启动时需要集中核实的输入

这些输入不必在准备阶段全部齐备；实施 AI 应先复用已确认的信息，缺关键项再一次性提出简短问题。

| 输入 | 用途与处理建议 |
| --- | --- |
| 小游戏 AppID、主体、开发者权限 | 工程已有 AppID，但其归属与当前账号权限未核实；不要直接当作已授权生产目标 |
| 微信云环境 | 是否已有环境、正式产品名称、环境 ID、地域、用途；已有环境优先评估复用 |
| 费用授权 | 可用套餐、月预算、是否允许新增资源/开通超额计费；未给预算时先给具体方案，不擅自下单 |
| 开发者工具与真机 | 可用电脑/工具版本、基础库、扫码和体验者权限、可参与验证的 Android/iOS 设备 |
| 首发商业化与历史数据 | 推荐首发先完成纯游戏内奖励/消费；真实支付、广告、现金奖励及历史游客数据迁移需按实际需求明确 |

不需要索取用户明文密码、AppSecret 或上传私钥。优先已有官方登录与可信运行时注入；确需密钥管理时按环境约定使用 Bitwarden Secrets Manager。

账号输入缺失时，可以推进源码、云端业务实现、资源、美术、构建配置和本地逻辑测试。需要真实微信身份、云部署或设备观察的验收项保留为阻塞项；不能因此把 Goal 降格为仅交付 mock。
