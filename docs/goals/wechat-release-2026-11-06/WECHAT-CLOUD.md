# 微信云服务与上线准备

本页是方案输入，不是已部署架构。官方资料查询日期为 **2026-11-06**；执行时仍需核对选定账号、地域、套餐、基础库与 SDK 的当前能力。

## 1. 先选一条可交付的云路线

| 路线 | 对本项目的价值 | 需要先验证的事项 |
| --- | --- | --- |
| CloudBase 云函数 + 持久数据库 + 云存储 | 适合身份、存档、任务/福利、领奖与排行等请求型业务；推荐作为第一候选 | 代表性/最长合法回放的 CPU、内存、超时与调用限制；运行时支持；事务、索引及资源费用 |
| 云托管中的 Node 服务 + 共享持久数据库 | 更接近已有 HTTP/worker 架构，适合回放计算或常驻进程确有需要的情况 | 明确是微信云托管还是 CloudBase 对应托管产品；确认小游戏调用路径、可信身份来源、冷启动、扩缩容、持久化与费用 |

两者都可服务微信，但账号入口、环境概念、SDK、网络与计费不能混用。先依据实际账号能力与回放成本选一个，不为抽象上的“灵活”同时部署两套。

**不要将 SQLite 文件放进弹性容器/云函数的临时磁盘，作为正式多实例数据库。** 现有单机 SQL、事务语义可以参考，存储实现需换为目标环境可用的共享持久数据库。

重要新资料：当前 CloudBase 资源点价格页写明，其 MySQL 能力自 2026-10-20 起不再支持新开通，已有实例不受影响。不要照旧教程把“新建 CloudBase MySQL”写成必经步骤；评估文档型数据库、PostgreSQL 或账号已有合适服务。这一说明针对该 CloudBase 产品，不泛化为腾讯云所有 MySQL 服务停止供应。

## 2. 身份与权限

- 使用 CloudBase 小游戏原生调用时，优先由云函数的 `getWXContext()` 获取本次可信 `OPENID/APPID`，并校验业务允许的应用和调用来源。不要相信客户端 body 自报的 openid。
- 此路径下无需为了“有登录接口”再造一套密码登录或强制额外 `code2Session`。若最终采用自有 HTTP 登录链，才按微信正式流程以 `wx.login` code 服务端换取身份并维护会话。
- 云托管若使用平台注入身份，明确可信入口及头部来源；开放公网请求不能靠同名任意 header 冒充微信用户。
- 本地 `wx-guest-*` 仅为当前占位；本地可玩不等于获得云端写入权限。登录/网络失败时清楚标明未同步、未入榜，不能显示虚假的保存/领取成功。
- 微信身份获取与用户资料授权是不同需求。游戏核心不强制手机号、通讯录、位置、真实头像昵称等无关信息；个人信息用途与隐私声明一致。
- 凭据使用已有官方登录或限定项目的安全注入。AppSecret、上传私钥、云管理员凭据均不进仓库、客户端包、日志或报告。

## 3. 最小必要的数据契约

以下是逻辑实体，不要求拆成独立微服务或每项一个集合：

| 实体/操作 | 要维持的关系 |
| --- | --- |
| 玩家 | 可信微信身份映射到服务端玩家；拥有状态、选择角色与存档有明确版本 |
| 对局 | runId 绑定玩家、seed、合法 loadout、规则/配置版本与开始时间；客户端提交操作记录，服务端验证结果 |
| 任务与手册 | 周期、条件、进度、领取资格与奖励配置由服务器判定；同一进度可供不同页面读取 |
| 钱包与库存 | 统一入账；领取标记与奖励、消费扣款与授予分别原子提交；禁止客户端直接改经济数据 |
| 幂等 | 重复结算/领奖/购买能返回同一业务结果；跨实例和重启后仍成立，不只靠进程内 Map |
| 排行榜 | 保持首次金币前规则、排序和个人最佳；权威回放结果决定是否入榜；与任务有效局规则分别判断 |
| 资源与配置 | 客户端包、服务器模拟与内容版本兼容；资产路径/清单有版本，缓存不能让旧素材长期遮住新部署 |

迁移优先复用 `packages/game/src/core` 的模拟、规则和配置，及 `apps/server/src/`、`server/` 中已存在的校验经验。网页 Cookie/Origin、HTML meta 页面凭据、网页入口代理不直接沿用为小游戏身份方案。

尽可能共用一局的权威结算结果，避免任务与排行榜分别计算后经济重复入账；同时保留两者不同的有效性规则，例如主动结束能否计任务与是否必须死亡才入榜。无需为了统一而改掉既有玩法。

客户端对钱包、拥有状态、领奖记录和榜单不得拥有直接任意写权限。数据库安全规则、服务端权限检查与索引应随业务实现一同交付。

## 4. 云部署的实际结果

选定方案后交付必要的代码、构建产物与可重复部署入口，以及：

- AppID/环境映射、运行时/依赖版本、函数或服务配置、数据库结构/索引/权限、初始化数据及资源上传清单。
- 开发/体验数据与正式数据明确隔离；可以是经验证的独立环境或严格等价方案，不让测试发奖/回放写正式余额和榜单。
- 微信包里的真实资源加载链：字体、图片、GLB、音频、配置；核对分包、远端存储/CDN、合法域名与缓存行为。不要以关闭域名校验的开发设置证明发布可用。
- 在授权云环境部署后，从小游戏真实身份发起请求，观察业务结果和持久数据，再重进读回。HTTP 200、函数已创建或控制台绿灯只证明各自阶段。
- 适量错误日志、请求关联信息、费用/容量提醒及必要的数据导出/备份说明；不为首发额外建设庞大管理后台。
- 若用户确有需要保留的已有正式数据，先明确迁移与失败恢复方案，再执行会改动数据的步骤；没有数据迁移需求时不制造迁移工程。

## 5. 费用边界

截至查询日，CloudBase 资源点价格页说明免费体验环境面向开发测试；免费云函数为 **3 秒超时、256M 内存且不可调整**，免费体验环境在小程序发布后到期时间变为上线后第 15 天。具体账号/套餐以控制台与当前条款为准。

因此：

- 不承诺“免费套餐长期上线”，也不根据旧快速开始文档自动创建两个免费环境。
- 先核实已有环境与计费模式，再估算调用、回放计算、数据库、云存储/CDN、日志等费用；体验环境只用于适合其限制的验证。
- 免费函数限制可能不适合现有长局回放，需实际测量后选择合适套餐/托管方式；不能通过信任客户端分数来省掉校验。
- 新开套餐、付费试用、资源扩容、自动续费或超限按量等新增费用需用户明确授权。已授权预算与目标明确后，不反复索取相同许可。

## 6. 技术可交付与公开上线

分别报告这些状态，不能合并成一句“已上线”：

1. **源码/包可构建**：逻辑检查、小游戏包与云端产物已生成。
2. **技术验收通过**：核心功能、视觉、设备运行和目标云数据已有真实证据。
3. **发布资料准备**：主体、名称/类目、图标简介、隐私保护、适龄提示、素材授权、自审与其他适用资料齐备。
4. **平台手续**：按主体、类目和商业化方式核实适用资质、小游戏/小程序备案、实名/防沉迷等要求；以官方当期规则和管理后台为准，不笼统保证免版号或保证通过。
5. **提审与正式发布**：用户确认实际版本和发布动作后办理；平台审核/备案等待属于外部进度，不通过修改代码伪造通过状态。

用户本次目标为“推进到可部署上线的程度”。执行 AI 应把可完成的实现、云部署、验证和发布材料推进到位；正式提审/公开发布等动作按届时明确授权执行。确实缺账号、预算、设备或平台资质时列出具体缺口，不以一份上线说明替代尚未实现的产品。

素材检查同时涵盖模型、插图、音效、音乐、字体、名称/肖像和第三方依赖许可证。保持已确认的角色身份；如果发现具体授权问题，说明影响与替代建议，不擅自宣称全部可商用或一律重命名。
