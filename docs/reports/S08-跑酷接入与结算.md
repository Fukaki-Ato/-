## 关键实现决策

1. **结算入口兜底**：`openSettlementPanel` 在 `PanelManager.open` 返回 null（尚未登记）时直接 `reward.grant(base,'settlement')` 并发 `run.settled`，避免合并波次前跑一局无收益；主会话登记面板后自动走面板流程。
2. **pendingBuff 清空时机**：按 S08 提示词「收集 `pendingBuff.*` 作为 `items` 传入（传完清空 flags）」在组装 `opts` 时清空；注意 docs/03 §2.6 写的是「launch 成功后清空」，两者在 launch 失败时语义不同（当前实现会消耗 buff，失败不返还）。
3. **未领取关闭自动发奖**：`onClose()` 统一兜底（返回/再来一局/外部关闭），随后 `flush()` + `redDot.refresh()`（红点链路本已被事件覆盖，显式刷新作保险）。
4. **双倍广告取消**：Toast「广告未完整观看，可再次尝试」，按钮恢复可点；成功后按钮置灰并展示 `RewardPopup(double)` 再关闭；广告期间面板被外部销毁则不补发（避免与关闭时 base 重复）。
5. **直接领取不弹 RewardPopup**（按 S08 提示词）；docs/04 §3.12 写「领取后 RewardPopup」，如需统一由主会话决策。
6. **再来一局**：由 MainMenu 传入 `onPlayAgain` 回调，面板先关闭并等 `waitClosed` 后触发，避免面板实例在关闭动画中复用导致数据错乱。
7. **成绩提交**：面板打开即 fire-and-forget `platform.cloud.submitScore`，失败仅 `log.warn`（Local 模式自动模拟）。
8. **炫耀一下**：分享标题按提示词，失败/取消仅 Toast（静默），不阻塞领取。
9. **debug 直通**：DebugPanel 用零延迟 Mock（不等待 mask/preload、不发 `run.started`、不消耗 pendingBuff），仅用于冒烟结算面板。

## 玩法正式接入的注意点（供主会话/S10 前决策）

- 当前 `GameplayLaunchOptions` 只有 `mode/characterId/items/seed`，**没有角色属性字段**；本会话未扩展契约。真实玩法读取角色属性的建议入口，按优先级：
  1. **推荐**：由主会话评审后在契约中扩展 `attrs?: CharacterAttrs`（或 `extra?: Record<string, number>`），MainMenu 在 `launch` 前用 `ctx.character.attrsOf(selected)` 预取传入；需同步 docs/02、docs/06 并在报告中声明。
  2. 过渡：玩法实现内部直接 `import { CharacterService }` 按 `characterId` 读取；缺点是玩法与外围服务耦合，违背 docs/06 §1「唯一边界」。
  3. docs/06 §5 提到「把属性放入 extra 由外围预取」，但 `extra` 目前在 `GameplayResult` 而非 `GameplayLaunchOptions`，采用前需先明确语义。
- 接入真实玩法只需替换 `createGameContext` 中的 `MockGameplayLauncher`（`IGameplayLauncher` 边界已稳定），UI/结算/事件链路无需改动；DebugPanel 的直通按钮可保留。
