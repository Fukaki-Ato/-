## 2. 派发规则（给用户）

1. 在**同一工作区**（`F:\OpenCode Projects\雷霆酷跑`）新建子会话；
2. 将 `docs/prompts/SXX-*.md` 的**全文**作为子会话开场提示词发送；
3. 一次只派发一个；等待其完成（含 git 提交与报告）；
4. 回到主会话回复「SXX 完成」；
5. 主会话执行验收（读报告、git log/diff、重跑 `npm run check`），输出结论：
   - ✅ 通过 → 派发下一个；
   - ⚠️ 需整改 → 按主会话给出的整改提示词再派发一个修复子会话（仍要提交）；
6. 全部通过后进入终验收。

**注意**：子会话可能改动 git 工作区，请不要同时开多个子会话，也不要手动编辑代码（除非主会话要求）。

## 3. 子会话统一要求（提示词中已包含，此处备忘）

- 开工先读：本表对应提示词 + `docs/00`–`docs/08` 中相关章节 + `assets/scripts/core/contracts.ts`；
- 只做本会话范围，不越界实现后续会话功能；不改公共契约（必要时在报告中申请）；
- 提交前 `npm run check` 全绿（ui 会话至少 `typecheck:cc`）；
- 完成后：git 提交（信息以 `SXX: ` 开头）→ 写 `docs/reports/SXX-*.md`，格式见 docs/07 §4。

## 4. 主会话验收流程（我执行）

1. 确认 git 提交存在且信息规范；`git log --stat` 核对改动范围；
2. 读取 `docs/reports/SXX-*.md`，对照 docs/07 验收表逐条核对；
3. 检查契约文件是否被非预期修改（`git diff` 检查 contracts.ts）；
4. 运行 `npm run check`（必要时 `npm test -- <过滤>`）；
5. 抽查关键实现（grep 禁止项：core 中的 `cc`/`wx` 引用、`console.log`、硬编码路径等）；
6. 输出验收结论与整改清单（如需要）。
