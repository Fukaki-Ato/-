## 任务清单

### 1. 结算计算（core/gameplay/Settlement.ts，纯 TS + 单测）

```ts
export function calculateSettlement(result: GameplayResult, run: RunConfig): SettlementResult
```

- 公式见 docs/02 §3.9：`base.gold = floor(coins*coinsToGold) + floor(score/scoreToGoldDivisor)`；`base.diamond = diamonds + floor(coins/diamondEveryCoins)`；`base.items` 暂空（预留掉落）；`double = base × 2`（金币/钻石翻倍，items 不去重）；
- 输入防护：字段缺失/负数按 0 处理；超大值 clamp 到 `CURRENCY_MAX`；测试覆盖 0 分、负输入、边界与倍数精确性。

### 2. 进入玩法（Settlement 前）

- 在「开始酷跑」按钮处接入 docs/06 §4 时序：
  - 收集 `pendingBuff.*` 作为 `items` 传入（传完清空 flags）；
  - `preload()`（超时 3s 忽略）→ emit `run.started` → LoadingMask → `launch(opts)`；
  - `launch` 成功 → emit `run.finished`（任务/成就/活动进度已在 S03 装配中响应）→ `calculateSettlement` → 打开 RunSettlementPanel；
  - `launch` 异常/拒绝 → Toast「本局无效」，不发奖，返回主界面并 error 日志；LoadingMask 必须保证关闭。
- 传入参数包含 `characterId` 与（预留）角色属性：如当前契约未包含属性字段，则通过 `items` 与 `mode` 之外的方式不要扩展契约；在报告中说明玩法真正接入时读取属性的建议入口（可建议在 S10 前由主会话决策）。

### 3. 结算面板（ui/panels/RunSettlementPanel.ts）

- 元素与流程按 docs/04 §3.12：标题、分数（大号）、距离、金币、奖励列表（`ctx.reward.describe(base)`）、按钮：
  - 「双倍领取」：`ctx.platform.ad.show('settlement.double')` → completed → `ctx.reward.grant(double,'settlement.ad')` → emit `run.settled`(doubled=true) → RewardPopup(double) → 关闭回主界面；取消 → Toast 并可再次点击（每局最多成功一次）；成功或领取后按钮置灰；
  - 「直接领取」：`grant(base,'settlement')` → `run.settled`(doubled=false) → 关闭；
  - 直接关闭（返回）→ 自动发放 base（保证不丢奖）并关闭；
- 防连点：领取操作进行中禁用全部按钮；面板关闭确保 `ctx.flush()`、`RedDots.refresh()`（context 事件链路已覆盖可简写）。
- 结算后（无论翻倍与否）调用 `ctx.platform.cloud.submitScore({...})`（fire-and-forget，失败仅日志；Local 模式自动模拟）。
