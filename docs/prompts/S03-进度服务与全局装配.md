## 任务清单

### 1. 进度类服务（core/services/）

依据 contracts.ts 与 docs/02、docs/03：

1. `TaskService.ts`：`track/onRunFinished/list/claim/claimAll/refreshIfNeeded/hasClaimable`。
   - 周期：daily 按游戏日、weekly 按 weekKey；`refreshIfNeeded` 检测 `date` 变化则清空该周期 progress/claimed 并 emit `task.changed`；
   - `track(metric, value, opts)`：`run.score.single` 取最高值，其余累加；progress clamp 到 [0, target]；进度未变化不 emit；
   - `onRunFinished(result)`：将 run.count+1、run.distance+result.distance、run.score.single、run.coins.total、run.diamonds.total 映射进 track；同时推进 `stats`（runs/totalDistance/totalCoins/totalDiamonds/bestScore/totalPlayMs）与 `stats.loginDays` 由装配层处理；
   - `claim`：claimable 校验（进度 ≥ target 且未领取）；重复领取→already_claimed；
   - `claimAll(type)`：返回 `{claimed, reward}` 汇总。
2. `AchievementService.ts`：与 TaskService 同构（无周期、无 refresh），`track/onRunFinished/list/claim/hasClaimable`。
3. `WelfareService.ts`：`signInState/signIn/dailyFreeAdClaimed/claimDailyFreeAd/refreshIfNeeded`。
   - `signInState`：`todaySigned = lastSignInDate === 当前游戏日`；days 状态计算规则：`day <= signInCycleDay → claimed`；`day === signInCycleDay+1 且未签到 → today`；其余 future；
   - `signIn`：已签→already_claimed；否则按当前 `signInCycleDay + 1` 取奖励、`reward.grant`、更新 cycleDay（=7 时归 0 表示下一轮从第 1 天开始）、lastSignInDate、signInHistory（去重、最多 90 条 FIFO）→ emit `welfare.changed`；
   - 每日免费广告：同日仅一次（用 flags 记录日期，如 `welfare.dailyAdDate`）。
4. `ActivityService.ts`：`list/get/claim/track/refreshIfNeeded/hasClaimable`。
   - 时间窗：`startTime/endTime`（本地时间字符串）与 `clock.now()` 比较得 `upcoming/active/ended`；`enabled=false` 的活动在 `list()` 中过滤；
   - 进度：`track` 累加（`run.score.single` 取最高）写 `activities.progress[id]`；过期后不可再 track（或 track 后不可领，二选一并测试固化）；
   - `claim(id, index)`：里程碑 claimable（active 且 progress ≥ target 且 index 不在 claimed 数组）；越界/重复/过期返回对应 reason；成功后 `reward.grant` 并按 index 记录 → emit `activity.changed`。
   - `login.days` 进度由装配层在每日首启时 track。
5. `RedDotService.ts`：`isOn/refresh/subscribe`。
   - 聚合规则见 docs/02 §4；`refresh()` 重新计算全部 key，翻转时 emit `reddot.changed` 并通知订阅者；
   - 订阅返回取消函数。

### 2. 组合根（core/services/index.ts）

实现 `createGameContext(opts: { platform: IPlatformAdapter; configSource: IConfigSource; now?: number })`，返回 `IGameContext`：

- 顺序：`config.loadAll()`（先取 app 配置）→ 构造 Clock（resetHour=dailyResetHour，now 可注入）→ storage=platform.storage → SaveRepository.load() → 构造各服务 → 注册事件联动；
- 事件联动（集中在本文件，服务内部不互相订阅）：
  - `day.changed` → 各服务 `refreshIfNeeded()` + `redDot.refresh()` + `stats.loginDays+1` + `activity.track('login.days', 1)`；
  - `run.finished` → `task.onRunFinished` + `achievement.onRunFinished` + `activity.track` 映射（在服务各自 onRunFinished 或此处统一调用，二选一并注释说明）；
- `refreshDaily()`：对比 `flags.lastGameDay` 与当前游戏日，变化则更新 flag、emit `day.changed`（首次启动也执行一次，使 loginDays 从 1 开始）；
- `markDirty()`：节流 500ms 写入 SaveRepository（更新 `save.updatedAt`）；`flush()`：立即写入；两者都要在测试中可控（可注入节流实现或暴露 `flush` 断言）；
- `useItem(id)`：按 docs/03 §2.6 实现（grant → reward.grant；runBuff+菜单使用 → `flags['pendingBuff.'+buffId]` 计数 +1；unlockCharacter → character.unlock）；
- `gameplay`：v1 使用 `MockGameplayLauncher`（delay/random 可注入，供测试），并在 `IGameContext` 上原样暴露；
- 平台适配器由调用方传入（Boot 负责选择 Local/WeChat）。
