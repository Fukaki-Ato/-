## 任务清单

### 1. 配置表与校验

1. 在 `assets/resources/config/` 创建 9 张配置表（schema 与示例见 docs/02 §3；数据量满足 UI 演示需要）：
   - `app.json`（单对象，cloudEnvId 留空 [本地模式]、privacyPolicy/userAgreement 用可替换的完整中文占位文本、debug=true）
   - `items.json` ≥3 条（含可在菜单使用的 runBuff 道具、材料）
   - `characters.json` ≥2 条（默认角色 + 付费角色；升级参数齐全）
   - `shop.json` ≥8 条，覆盖四个页签（gold/diamond/props/special），含：钻石购金币、金币购道具、广告免费商品（viaAd+dailyLimit）、CNY 充值商品（`productId`、`iosVisible:false`）
   - `tasks.json` ≥6 条（每日 ≥4、每周 ≥2，覆盖 run.count/run.distance/run.coins.total/login.days/shop.buy.count）
   - `achievements.json` ≥4 条
   - `welfare.json`（7 天签到 + 每日免费广告奖励）
   - `activities.json` ≥2 条（一条进行中、一条未开始或已结束，用于 S09 验证时间窗）
   - `run.json` ≥1 条（classic 模式，结算参数与 buffs）
2. `core/config/validate.ts`：结构校验（数组表、必填字段、类型、id 唯一）与引用校验（shop.gain 中的 item/character 存在、角色 unlock 引用存在、任务/成就 metric 合法、welfare 天数连续、run 结算数值 > 0 等）。错误信息包含表名、条目 id/索引与字段名；`validateConfigs` 返回错误列表，ConfigService 在 `debug=true` 时打印全部并抛出第一个错误。
3. `core/services/ConfigService.ts`：实现 `IConfigService`；构造注入 `IConfigSource`；`loadAll()` 加载全部表、执行校验、构建索引（Map）；`run(mode)` 找不到时抛错（调用方保证 mode 合法）。

### 2. 经济类服务（core/services/）

严格按 contracts.ts 接口与 docs/03 行为实现，全部构造注入 `ServiceDeps`（save/events/clock/log/markDirty）与所需服务：

1. `InventoryService.ts`：`count/add/remove/all/use`。
   - add/remove 数量非负整数化；不足返回 `{ok:false, reason: FailReason.Insufficient}`；
   - `use`：数量不足→insufficient；道具不存在/无 useEffect→`unsupported`；消耗 1 并返回 `effect`（**不应用效果**，由 S03 的 `context.useItem` 负责）。
2. `CurrencyService.ts`：`get/canAfford/add/spend`；上限 `CURRENCY_MAX` 夹取；`add` 负数防护（忽略并 warn）。
   - `spend` 支持 `Cost.items`：构造注入 `IInventoryService`；顺序为「先全量校验（货币+道具）→ 移除道具 → 扣货币」，中途不可失败（单线程下先校验保证原子）；任何不足返回 `insufficient` 且不变更任何数据。
3. `CharacterService.ts`：`list/get/current/unlock/upgrade/select/attrsOf`。
   - 升级费用公式 `ceil(baseCost.amount * costFactor^(level-1))`（货币按类型；items 型费用同理按数量），满级返回 `max_level`；
   - 解锁：`default`（首个角色已解锁）/`currency`（走 currency.spend）/`item`（走 inventory.remove）/`condition`（v1 返回 `locked`，注释预留）；
   - `select`：未解锁→`locked`；属性 = `baseAttr + growth*(level-1)` 取整；
   - 每次变更 emit `character.changed`。
4. `RewardService.ts`：`grant(bundle, source)`：货币→currency.add（reason 记录 source）、道具→inventory.add、角色→character 解锁（已解锁则跳过且不报错）；空 bundle 安全；`describe(bundle)` 返回 `RewardDisplay[]`（道具/角色名称与图标查表，查不到用 id 兜底）。
5. `ShopService.ts`：`list/buy/claimAd/claimPay/refreshIfNeeded`。
   - `ShopGoodsView`：`remainingDaily`（无 dailyLimit 为 null）、`soldOut`、`affordable`（CNY 商品恒 true，由平台侧处理）、`needAd`、`lockReason`；
   - `buy`：不存在→not_found；限购→limit；CNY→返回 `needPay:{productId, priceFen: amount}`；viaAd→返回 `needAd:true`（不发奖）；普通→`currency.spend`→`reward.grant`→记录 `dailyBought`→emit `shop.changed`；
   - `claimAd`/`claimPay`：再次校验限购后直接 grant；重复调用受每日限购约束（默认 dailyLimit 不存在则仅限一次？——无 dailyLimit 的广告商品按 `dailyLimit ?? 1` 处理，写入 `adClaimed`）；
   - `refreshIfNeeded`：`dailyRefreshDate` 与当前游戏日不一致时清空 `dailyBought/adClaimed` 并更新日期、emit `shop.changed`。
   - 注意：`iosVisible` 仅存配置，由 UI 过滤。

### 3. 测试（tests/services/ 与 tests/config/）

必须覆盖（除正常路径外的失败与边界）：

- Config：合法加载；重复 id 报错；引用缺失报错（如 shop.gain.items 指向不存在的道具）。
- Currency：上限夹取；负数防护；`spend` 不足/负数/含道具的原子性（道具不足时货币也不得扣除）。
- Inventory：remove 不足；use 消耗与返回 effect；无 effect 返回 unsupported。
- Reward：混合奖励（金+钻+道具+角色）一次发放；describe 名称图标正确。
- Character：默认角色状态；货币解锁；升级 1→2、2→3 费用与属性；余额不足；满级；选择未解锁角色被拒。
- Shop：四页签列表；正常购买（扣费+到账+限购计数）；余额不足；CNY 返回 needPay 且不扣费；广告商品 buy 返回 needAd、claimAd 到账、二次 claimAd 受限；跨天刷新（注入 Clock 伪造时间）。
