# 01 架构与工程规范

## 1. 技术选型

| 项 | 选择 | 版本基线 | 说明 |
| --- | --- | --- | --- |
| 引擎 | Cocos Creator | 3.8.x（建议 3.8.8） | 与 `@cocos/creator-types` 同小版本 |
| 语言 | TypeScript | 5.x | `strict: true` |
| 目标平台 | 微信小游戏 | 微信开发者工具最新稳定版 | 构建平台 `wechatgame` |
| 单测 | Vitest | 最新稳定版 | Node 环境，仅测 core |
| 类型检查 | tsc | 随 TypeScript | 无编辑器也可检查 `cc` 代码（借助 creator-types） |
| 包管理 | npm | Node 18+ | 仅 devDependencies，运行时不引入 npm 包 |
| 云 | 微信云开发 | wx-server-sdk | 云函数单独目录，见 docs/05 |

**关键决策**：

1. **界面纯代码化**：不使用 Prefab，不手工依赖场景内节点。全部界面由 TypeScript 在运行时构建，场景中只需一个挂载 `Boot` 组件的空场景。这保证 LLM 子会话可纯文本开发与代码评审，避免二进制/JSON 场景资产出错。
2. **core 与引擎解耦**：业务逻辑（经济、任务、活动等）全部放进 `assets/scripts/core`，禁止 `import 'cc'`，从而可以用 Vitest 在 Node 中完整验证。
3. **双平台适配**：`IPlatformAdapter` 有 Local 与 WeChat 两个实现，开发期用 Local（存档走 wx/localStorage/内存三级降级，广告/支付/云返回模拟结果）。
4. **资源占位降级**：所有图片加载统一走 `ui/framework/Assets.ts`，资源缺失时自动绘制占位图，素材后置不影响功能验收。
5. **配置驱动**：商店、任务、活动、角色等全部由 JSON 配置表驱动，运营调整不改代码。

## 2. 分层架构

```
┌─────────────────────────────────────────────────────────┐
│ UI 层  assets/scripts/ui（依赖 cc）                      │
│  boot: Boot/GameRoot                                     │
│  framework: UIRoot/PanelManager/BasePanel/Toast/...      │
│  panels: MainMenu/Shop/Welfare/Task/Achievement/...      │
└──────────────────────────┬──────────────────────────────┘
                           │ 仅依赖 contracts.ts 与 core 服务接口
┌──────────────────────────▼──────────────────────────────┐
│ 核心层  assets/scripts/core（纯 TS，禁止 cc）             │
│  framework: EventBus/Clock/Storage/SaveRepository/Logger │
│  services: Config/Currency/Reward/Inventory/Shop/        │
│            Character/Task/Achievement/Welfare/Activity/  │
│            RedDot + 组合根 createGameContext              │
│  gameplay: Settlement 计算/MockGameplayLauncher           │
│  platform: LocalPlatformAdapter/LocalCloudService         │
└──────────────────────────┬──────────────────────────────┘
                           │ IPlatformAdapter / IGameplayLauncher
┌──────────────────────────▼──────────────────────────────┐
│ 适配层                                                    │
│  platform/wechat（S10）｜云函数 cloudfunctions（S10）      │
│  跑酷玩法实现（外部模块/后续会话，见 docs/06）              │
└─────────────────────────────────────────────────────────┘
```

**依赖规则（验收会检查）**：

1. `core/**` 不得出现 `from 'cc'`、`wx.`、`document`、`window` 等引擎/宿主 API；宿主差异一律通过接口注入。
2. `ui/**` 只能通过 `core/contracts` 与 `core` 服务（`IGameContext`）访问业务，不得直接改 `save` 内部字段以外的逻辑；简单 UI 状态可自带。
3. `ui/**` 不得互相 import 面板实现（通过 `panels/index.ts` 注册表解耦）。
4. 全部模块使用**相对路径**导入，不配置路径别名。
5. 不新增运行时 npm 依赖。

### 4.2 类型检查三配置

| 文件 | 用途 | 包含 | 说明 |
| --- | --- | --- | --- |
| tsconfig.json | 编辑器与 Cocos 构建使用 | assets | extends `./temp/tsconfig.cocos.json`（编辑器首次打开后生成） |

| tsconfig.cc.json | CLI 检查 ui | `assets/scripts/**`、`typings` | 经 `typings/cc.d.ts` 引入 creator-types 的 `declare module 'cc'` |

## 5. 场景与启动策略

- 唯一场景 `assets/scenes/Main.scene`：`Canvas` → 空节点挂载 `Boot` 组件。
- `Boot` 职责：初始化 UIRoot → 创建平台适配器 → `createGameContext()` → 载入配置与存档 → 隐私/登录 → 打开主界面。
- 场景生成方式（二选一，见 docs/08）：
  1. 编辑器可用时：新建空场景，创建 Canvas，新建节点挂 `Boot`，保存为 `assets/scenes/Main.scene`；
  2. 由 S05 尝试生成最小合法场景 JSON，失败则回退方式 1（不允许因此阻塞会话）。
- 所有面板节点的生命周期由 `PanelManager` 管理，场景中不预置任何面板节点。

## 6. 代码规范

1. **命名**：文件 `PascalCase.ts`（类型/组件）、`camelCase.ts`（工具函数）；接口 `I` 前缀；常量 `UPPER_SNAKE`。
2. **注释**：仅在必要处写中文注释解释“为什么”；不写“是什么”的废话注释。
3. **字符串**：界面文案中文，集中在面板/组件内，禁止散落魔法字符串（奖励展示除外）。
4. **错误处理**：服务失败返回 `OpResult`/`Result`，UI 层负责提示；禁止静默吞错。资源加载失败必须降级且仅告警一次。
5. **数值安全**：货币/道具数量的加减必须过 `Math.max(0, ...)` 与整数化；扣费与发货必须原子（先校验后扣除再发放，过程中不可早发）。
6. **事件**：业务状态变更后由服务 `emit` 对应事件，UI 监听刷新；禁止 UI 直接调用另一个面板刷新。
7. **存档**：任何写操作后调用 `markDirty()`，由 context 节流保存（默认 500ms）。
8. **禁止**：`any` 滥用（确需时局部 + 注释）、`console.log` 直出（统一用 Logger）、硬编码资源绝对路径（统一走 Assets 工具与配置表）。
9. **文件规模**：单文件建议 ≤ 400 行；单面板超过时拆 widgets。

## 7. 无编辑器验证策略

| 检查项 | 命令 | 适用会话 |
| --- | --- | --- |
| core 单元测试 | `npm test` | S01–S03、S08（结算计算） |
| core 类型检查 | `npm run typecheck:core` | 全部 |
| ui 类型检查（含 cc） | `npm run typecheck:cc` | S04–S10 |
| 提交前总检查 | `npm run check` | 全部（core 未就绪前 S01 提供最小可用版本） |

编辑器安装后由用户执行冒烟：打开工程 → 运行预览 → 按 docs/07 清单点击。子会话报告需列出“需要人工在编辑器/真机验证的事项”。

## 8. 微信小游戏构建（S10 细化，先行约束）

- 构建平台：`wechatgame`，竖屏，设计分辨率 750 × 1624（宽适配，Widget 锚定）。
- 主包体积控制：核心代码与配置在主包；美术资源超过 4MB 时迁移到 `assets/bundles/` 分包（S10 按实际体积处理）。
- `appid` 使用测试号或用户提供的正式 appid；云环境 ID 写入 `resources/config/app.json` 的 `cloudEnvId`。
- 引擎裁剪：构建面板关闭未使用模块（3D、物理、粒子等），保留 2D、UI、音频、Tween。
