# 06 跑酷对接协议

> 本协议定义外围系统与跑酷玩法之间的唯一边界。玩法团队/后续会话只需要实现 `IGameplayLauncher` 并替换 Mock 实现即可接入。

## 1. 边界原则

1. 外围系统不认识玩法的内部实现（场景、节点、物理、关卡），只认识两个数据：**进入参数**与**结算结果**。
2. 进入玩法前，由主界面（S08）组装 `GameplayLaunchOptions` 并调用 `gameplay.launch()`；返回 Promise 完成即代表一局结束。
3. 局内复活、局内广告等属于玩法内部事务；外围只读取 `revivedCount` 用于统计。
4. 结算奖励的计算与发放属于外围系统，玩法只上报原始数据。

## 2. 接口（contracts.ts 节选）

```ts
export interface GameplayLaunchOptions {
  mode: string;                 // 'classic' 等，对应 run.json
  characterId: string;          // 当前选择角色
  items?: string[];             // 本局生效道具（由 UI 传入）
  seed?: number;                // 可选随机种子（回放/测试）
}

export interface GameplayResult {
  mode: string;
  score: number;                // 本局得分
  distance: number;             // 米
  coins: number;                // 拾取金币数
  diamonds: number;             // 拾取钻石数
  durationMs: number;
  revivedCount: number;
  extra?: Record<string, number>; // 预留自定义指标
}

export interface IGameplayLauncher {
  readonly isMock: boolean;
  preload(): Promise<void>;
  launch(opts: GameplayLaunchOptions): Promise<GameplayResult>;
}
```

## 3. Mock 实现（S01 提供，S08 接入流程）

- 位置：`assets/scripts/core/gameplay/MockGameplayLauncher.ts`（纯 TS，可单测）。
- 行为：`launch()` 延迟 2–4 秒（可配置，测试注入 0）；随机生成 `score 300–3000`、`distance 200–1200`、`coins 20–300`；必掉 0–2 钻石；`revivedCount=0`。
- 用途：无玩法时完整联调主界面→结算→任务进度。
- 外部特性：`isMock = true`；主界面在 Mock 模式显示角标"沙盒模式"（仅 debug）。

## 4. 集成时序（S08 实现）

```
MainMenu.onStart()
  → LoadingMask.show('准备出发...')
  → ctx.gameplay.preload()（超时 3s 忽略）
  → ctx.events.emit('run.started', opts)
  → result = await ctx.gameplay.launch(opts)
  → ctx.events.emit('run.finished', result)   // 任务/成就/活动进度立即推进
  → Settlement.calculate(result, runConfig)   // 基础与双倍奖励
  → RunSettlementPanel.open({ result, base, double })
     用户点击「双倍领取」→ platform.ad.show('settlement.double')
       成功 → reward.grant(double, 'settlement.ad') → emit run.settled(doubled=true)
     用户点击「直接领取」→ reward.grant(base, 'settlement') → emit run.settled(doubled=false)
     用户直接返回（无操作）→ 关闭时自动发放 base（保证不丢奖励）
  → ctx.flush() → RedDots.refresh() → 返回主界面
```

约定：

- 结算面板打开期间，`run.finished` 已发射，任务进度已更新；奖励发放以 `run.settled` 为准。
- `settlement.double` 广告每局最多一次；广告取消可重试，但不可重复发放。
- 若 `launch()` 抛错/超时（> 10 分钟视为异常）：Toast"本局无效"，不发放奖励，返回主界面并记录错误日志。

## 5. 玩法接入检查清单（给玩法团队）

- [ ] 实现 `IGameplayLauncher`，导入玩家传入的角色属性（`CharacterService.attrsOf(characterId)` 可由外围在 launch 前通过 opts 扩展；v1 把属性放入 `extra` 由外围预取）。
- [ ] 一局结束务必 resolve `GameplayResult`，字段非负且为整数。
- [ ] 中途退出（用户杀进程）由微信生命周期处理，外围不补发。
- [ ] 不要在外围存档中直接写数据；需要发奖时通过返回结果表达。
- [ ] 真机性能：首帧加载建议在 `preload()` 完成。
