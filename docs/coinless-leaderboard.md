# 第一次吃金币前距离全服榜与金币排

## 玩家规则

- 大厅「排行榜」打开全服前 50 名及自己的最佳纪录；结算页也可打开。
- 记录**从开局到第一次实际拾取金币之前**的距离和分数；第一次入账前冻结纪录，后来继续跑、吃金币或加分都不延长这段成绩。磁铁、技能批量吸取同样算拾取，即使倍率折算后的金币余额为零也会停止计距。
- 冻结点使用实际拾取时的模拟距离，而不是金币的世界坐标。分数包含此前的里程、擦身与已经生效的技能加分，不包含第一枚金币及之后的奖励。批量吸币只冻结一次；当前瞬移技能先收币再位移，所以不会将随后整段瞬移加入纪录。
- 跑到死亡结算后上传，不提前结束正常跑局；没吃金币的局仍取整局距离和分数。中途 Esc 退出、debug/test 局不上传。
- 按距离降序，同距离按分数降序，完全相同的纪录保留先提交者。每个匿名游客只保留一条最佳纪录。
- 身份由同源 HttpOnly Cookie 保持，没有账号登录；清除站点数据或换浏览器会成为新游客。
- 开局取得服务端 seed 和一次性比赛票；结束仅上传步号及操作。服务端重放完整死亡跑局并计算第一次金币前的纪录，不信任客户端提供的距离/分数。结算页同时展示整局统计与这段榜单成绩。配置不一致或服务故障时可继续普通跑局，结算会注明不入榜。
- 重放校验保证符合模拟规则，不能保证操作来自人类；游客榜也不能阻止一个人使用多个浏览器身份。
- 本次规则 ID 从 `coinless-v1-*` 改为 `first-coin-v1-*`，前后端需同步升级。旧的整局零金币成绩本身就是一段完整的吃币前纪录，继续保留；SQLite 表与 Cookie 身份不变，不清榜、不改库。历史吃币局原本没入库，不能补算它们的前缀成绩。

## 金币生成调整

- `config/game.json` 的单/双/三道抽取权重由 `70/25/5` 改为 `50/20/30`。这是抽取概率；障碍占用会削减能实际铺出的车道数，断档补链也会增加车道。
- 地面同组多道金币对齐起点、终点和链号，仍避开障碍、保留模板边距及单道断档补链。
- 桶范围改为 `3–4 / 5–6 / 7–8` 枚，间距仍为 `1.5m`。
- `coins.jumpSpanRatio=0.9` 限制每排首尾跨度。不是直接套用整个滞空时间：跳起/落地附近仍可能吃币，因此使用与拾取判定同源的 **1.05m 净空高度**，按固定步长计算正常无增益跳跃的避币窗口，再乘 90%。生成段速度按基础速度、距离加速和最大速度估算，不依赖弹跳鞋/飞行增益。
- 基础/中速/极速测试通过实际拾取逻辑寻找合法起跳时机，验证最长同步排可不吃币跃过；受击减速、主动俯冲等仍会缩短实际净空窗口。
- 随机抽取次数和分布变化会改变同 seed 后续赛道；15 例 golden 已检查变化并更新，只改期望结果，不改输入编排。

## 验证与边界

`npm run build` 后可运行：

```sh
node --test tests/first-coin-record.test.mjs tests/coinless-gameplay.test.mjs tests/trackGen.test.mjs tests/leaderboard-flow.test.mjs tests/leaderboard-ui.test.mjs tests/leaderboard-server.test.mjs
npm run check
TR_WEB_BASE=/thunder-run/ npm run build:web
TR_WEB_BASE=/thunder-run/ TR_NO_OPEN=1 npm run preview:web -- --host 127.0.0.1 --port 8778 --strictPort
```

服务端运行、反向代理、持久化与安全限制见 [leaderboard-server.md](leaderboard-server.md)。Web 提供 DOM 页面及联网客户端；WX 尚无排行榜网络集成，不将 bundle 检查当作 WX 真机验收。

子路径构建的 Vite preview 也须使用相同 `TR_WEB_BASE`；否则 HTML 的 fallback 可返回 200，但 `/thunder-run/assets/...` 模块会 404，页面无法启动。浏览器启动验证以入口模块加载和实际菜单出现为准，不只检查 HTML 状态码。
