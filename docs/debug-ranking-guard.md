# 调试模式与服务器排名隔离

## 服务端规则

正式站默认关闭 `debug`、`test`、`anim` 和 `ui=demo` 页面入口，参数按 URL 解码、忽略键大小写；`debug=false` / `test=0` 仍按调试请求处理。不是相信客户端提交 `debug:false`，也不靠 Referer 缺失来认定正常。

正常入口 `/thunder-run/` 或 `/thunder-run/index.html` 由 Node 页面网关处理：

1. 服务器签发不含客户端模式声明的 HttpOnly 浏览器排名会话，以及每个文档独立的随机页面凭据。Cookie 的路径同时覆盖 HTML 与 API；页面凭据仅放在该次响应的 `<meta name="tr-rank-page">` 中，不写入浏览器长期存储。
2. 请求比赛票据须同时提供服务器认可的 Cookie、页面凭据、角色和规则 ID。票据绑定浏览器会话、文档凭据及原游客身份。
3. 服务器观察到调试入口请求时，撤销该浏览器会话。来自已配置可信站点的调试页面 Referer 也可作否决信号；外站伪造的调试样式 Referer 不得撤销正常会话。
4. 成绩提交时验证绑定；重放 worker 返回后、写 SQLite 前再检查撤销和过期，避免重放期间进入调试仍写分的竞态。
5. 正常页面重新进入后使用新的会话/文档凭据，不能恢复之前被撤销的票据。正常多标签页共享浏览器 Cookie、各有文档凭据；不能拿另一个文档凭据上传原票据。调试会使同一浏览器的旧排名文档失效，其他正常标签页需重新加载。

规则 ID 升级为 `first-coin-v2-*`，**计距和计分不变**；API `runs` 新增必填 `pageId`，`runs/submit` 也须带原文档的 `pageId`。客户端不允许提交分数、距离、模式或 buff 状态。取消票据、只读榜单及健康检查不要求排名文档凭据。

会话最长 6 小时，开赛时续期到足以覆盖最大跑局；会话/文档容量和入口请求频率均有界。容量不足不会发排名凭据；正常页面仍可普通跑步。服务重启会使排名会话和进行中的票据失效，原 Cookie 游客身份和最佳纪录不会清除。

## 构建与本机调试

- 官方生产构建：`VITE_TR_ALLOW_DEBUG=0 TR_WEB_BASE=/thunder-run/ npm run build:web`。URL 不能启用测试面板、测试 API、动画锁、探针、UI demo 或 `char` QA 预设。普通选角和正常游戏仍可用。
- 开发服务器天然允许调试；私有 QA 生产构建须显式 `VITE_TR_ALLOW_DEBUG=1`。Node 默认仍拒调试 HTML；仅本机/独立 QA 服务可设 `TR_LEADERBOARD_ALLOW_DEBUG_PAGES=true`，调试 HTML 不获得排名文档凭据。
- Vite dev/preview 使用服务器中间件观察实际 HTML 请求，向本机 Node 入口发 HEAD 获取凭据，并正确重写 Cookie 路径；保留 Vite HTML 转换与 HMR。不设公开的“声明自己是正常模式”签发接口。
- 本机服务不可用时，Vite 可以普通离线测试但没有排名凭据。正式页面代理依赖 Node：不可用时不签发凭据，不能默认为可排名。

## 部署

需在用户合并后一起发布前端、Node 与入口代理；只更换旧静态前端不能建立服务器会话边界。

- Node 环境设置 `TR_LEADERBOARD_WEB_ROOT=/usr/local/nginx/html/thunder-run`、`TR_LEADERBOARD_ALLOW_DEBUG_PAGES=false`，数据库仍用现有外部持久路径，不复制测试库。
- 在现有正式 vhost 用 `server/nginx-leaderboard.conf` 替换旧 HTML/API location。HTML 不再由静态 location 旁路；资产仍由原静态 location 提供。不要新增 vhost、端口、TLS 或防火墙规则。
- 移除临时先返回 403 的 query 拦截：最终调试请求必须到达 Node 才能撤销旧会话。检查 `nginx -t` 后 reload，验证所有入口别名和编码参数。
- HTML 会话响应 `Cache-Control: no-store`，禁止嵌入框架（CSP `frame-ancestors 'none'` / X-Frame-Options DENY）。不得缓存或复用含页面凭据的 HTML，不将 Cookie/页面凭据/比赛票据写入日志或发布证明。
- 发布字节核对仍检查磁盘 entry 与构建产物相同；网络 HTML 因每次注入随机凭据而不同，须仅在内存中移除那一个服务器注入的 meta 后核对剩余字节。资产仍可直接逐字节核对；不要把含凭据的原始 HTML 保存为公开发布证据。
- 回滚须同时还原旧入口路由、服务与前端，并保持排行榜数据库；不要仅回滚一个协议组件。

## 能保证与不能保证的边界

可以保证：服务器观察到的调试会话及其文档/票据不能排名；正常排名始终由不可由客户端替换配置的服务器模拟重算，调试器增益、无敌或客户端伪造分数不直接入库。

不能保证：浏览器代码完全未被修改、真人输入、防所有外挂或明文 HTTP 上的网络攻击。攻击者始终可以请求正常页面再提交合法操作重放，网页凭据不是硬件远程认证。HttpOnly 和禁止 iframe 不会消除这个基本限制。老记录未保存可追溯的页面模式，不能据此猜测并删除历史成绩。

## 验证与测试生命周期

测试包含无/伪造/复制凭据、文档与票据错配、进入调试撤销、重新进入正常页不能救回旧票、worker 等待期间撤销/过期不得写分、外站 Referer 不得撤销正常会话、本机 QA 无排名凭据、Vite Cookie 路径/HMR 与生产禁调试。

Vite 网关的 HTTP 集成测试使用最小 HTML fixture，并关闭预转换，不把整个应用依赖图暖加载混入一次性生命周期测试。完整应用另用浏览器验证。Vite preview 应调用其 `close()`，不能只关闭 `httpServer`。本次诊断发现整应用预转换可能在测试关闭后继续加入跨包文件 watcher，使测试断言通过但进程不退出；检查真实资源并缩小 fixture，不用强制退出掩盖它。

该版验证：`npm run check` 636 项测试及全部质量门禁通过，默认生产构建通过且不生成测试面板 chunk。隔离生产浏览器验证了正常完整跑局入榜、HttpOnly 会话、无六类 QA 全局、编码调试入口 403、旧页面/票据拒绝与重新进入正常可参赛；隔离开发浏览器验证测试面板和无敌开关仍可用，但没有排名文档凭据，直接请求排名票据返回 403。未向正式榜单写入测试成绩。独立安全审查提出的外站 Referer 撤销和生产 `char` QA 预设均已修正并回归。
