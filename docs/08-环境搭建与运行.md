## 2. 首次打开工程（推荐流程）

S01 完成后，工程根目录已经具备 `package.json / tsconfig / assets / docs`。

1. 打开 Cocos Dashboard → 项目 → **打开项目** → 选择本目录 `F:\OpenCode Projects\雷霆酷跑`；
2. 若 Dashboard 提示“不是有效项目”（缺少 settings/temp 等），采用兜底流程：
   - Dashboard 新建一个空白 3D 项目到临时目录（版本选同一 3.8.x）；
   - 用新项目中的 `settings/` 覆盖本工程（若本工程没有），保留本工程 `assets/`、`package.json`、`tsconfig*.json`；
   - 重新“打开项目”。
3. 编辑器首次打开会自动生成 `library/ temp/ local/ profiles/` 与资源 `.meta`，属正常现象，均已被 .gitignore 忽略；
4. 若提示脚本编译错误，先执行 `npm install`（工程依赖 @cocos/creator-types 仅用于 CLI 类型检查，不影响编辑器）。

## 3. 场景与启动（编辑器内，一次性）

S05 会提供两种方式，优先自动生成 `assets/scenes/Main.scene`：

1. 若场景文件正常：直接打开 `assets/scenes/Main.scene`，确认 `Canvas` 下存在挂载 `Boot` 组件的节点；
2. 若场景无效：资源管理器右键 `assets/scenes` → 新建 → Scene，命名为 `Main`；在层级管理器新建 Canvas（若有默认相机保留）；在 Canvas 下新建空节点 `Boot`，添加组件 `Boot`；保存。

**S05 结果：自动**。已生成 `assets/scenes/Main.scene`（Canvas + Camera + Boot 节点；Boot 组件按压缩 UUID 引用脚本），并通过 Cocos Creator 3.8.8 无头构建与浏览器运行冒烟；如后续场景损坏，按上文第 2 条手动重建。

**预览**：编辑器顶部预览按钮 → 浏览器模拟器。首次应看到启动加载并进入主界面（占位图形）。

## 4. 微信开发者工具联调（S10）

### 4.1 构建 wechatgame

1. 菜单「项目 → 构建发布」→ 平台选 **微信小游戏（wechatgame）**；
2. 通用选项：`debug`（联调 `true`，提审 `false`）、`md5Cache`（提审建议开）、构建路径 `build/wechatgame`、设计分辨率与 docs/04 对齐（750 × 1624 竖屏，Fit Width）；
3. 平台选项：
   - **AppID**：微信公众平台的小游戏 AppID；无正式 appid 可先用测试号（测试 appid 仅供本地预览，不能提审）；
   - **设备方向**：竖屏（portrait）；
   - **引擎模块裁剪**（高级选项）：保留 `base / gfx-webgl / gfx-webgl2 / ui / audio / tween`；未使用的 `physics-* / particle / terrain` 可去勾；跑酷玩法接入后按实际依赖重新勾选；
   - **开放数据域**：默认关闭；好友榜方案见 §4.5；
4. 命令行构建（CI 用）。注意平台专属参数（appid 等）必须放在 `packages.wechatgame`，顶层 `appid=...` 不会生效（已实测被忽略）。推荐导出构建面板配置或使用参数 JSON：

   ```json
   {
     "platform": "wechatgame",
     "debug": true,
     "buildPath": "project://build",
     "packages": {
       "wechatgame": { "appid": "wx0000000000000000", "orientation": "portrait" }
     }
   }
   ```

   ```bash
   "C:\Cocos\Editor\3.8.8\CocosCreator.exe" --project "F:\OpenCode Projects\雷霆酷跑" --build "configPath=<上述 JSON 路径>"
   ```

   退出码（官方文档）：**36** 成功，32 参数不合法，34 构建过程出错。

### 4.2 导入与首次运行

1. 微信开发者工具 → 导入项目 → 选择 `build/wechatgame`（appid 取构建面板/产物 `project.config.json`）；
2. 首次运行应看到：启动页 → 文档隐私弹窗 → **微信原生隐私弹窗**（基础库支持时）→ 登录（`cloudEnvId` 为空/云函数未部署时自动游客降级）→ 主界面；
3. 分享：右上角胶囊「…」→ 转发，标题取 `app.json` 的 `share.title`；
4. 广告与支付需先配置 §4.4 并重新构建；未配置时广告走模拟逻辑、支付返回 unsupported；
5. 真机预览：工具栏「预览」扫码，回归清单见 §4.6。

### 4.3 云开发配置与云函数部署

1. 微信开发者工具 → 云开发 → 开通环境，记录**环境 ID**；
2. 云开发控制台 → 数据库：按 `cloudfunctions/README.md` 创建 `players / saves / scores` 三个集合；
   - 权限：三个集合均选「所有用户不可读写」（客户端只经云函数访问，最小权限）；
   - 索引：`players._openid` 唯一、`saves._openid` 唯一、`scores._openid` 唯一 + `scores.score` 降序；
3. 同步公共代码并部署云函数：

   ```bash
   cd cloudfunctions
   node sync-common.js
   ```

   微信开发者工具左侧「云函数」→ 对 `login / syncSave / submitScore / getLeaderboard` 逐个右键：
   - 首次：**创建并部署：云端安装依赖**；
   - 更新：**上传并部署：云端安装依赖**；
4. 将环境 ID 填入 `assets/resources/config/app.json` 的 `cloudEnvId`（仓库中留空，禁止提交真实环境 ID），重新构建；
5. 验证：清除缓存后启动，`save.profile.isGuest === false`；排行榜「世界」页签出现真实数据；删除云函数或断网启动时自动游客降级、排行榜显示「离线模式」；
6. 云函数日志：云开发控制台 → 云函数 → 日志（排查 `DB_ERROR` / `INVALID_SCORE` / `STALE_SAVE`）。

### 4.4 广告位与支付配置（`assets/resources/config/app.json`）

| 字段 | 用途 | 不配置时的行为 |
| --- | --- | --- |
| `adUnits['settlement.double']` 等 4 项 | 激励视频广告位 ID（微信后台 → 流量主 → 广告位管理创建） | 空串走模拟广告（可交付/可取消），保持可测 |
| `pay.offerId` | 米大师 offerId（虚拟支付进件后获取） | 支付返回 `unsupported` |
| `pay.mode` / `pay.env` / `pay.zoneId` | 道具直购（goods）/ 正式 0 沙箱 1 / 分区 | 默认 goods / 0 / 1 |
| `share.title` / `share.imageUrl` | 统一分享文案与截图 | 默认「雷霆酷跑，一起来跑！」 |
| `debug` + `forceLocal` | 真机强制 Local 平台（排查用） | 按 `wx + cloudEnvId` 正常选择平台 |

支付流程：`ShopService.buy` 返回 `needPay(productId)` → `ShopPanel.payFlow` → `platform.pay`（Android 走 `wx.requestMidasPayment`，iOS/其他返回 `unsupported`，UI 隐藏充值入口）→ 成功后 `claimPay` 发奖；服务端校验为后续加固项（见 docs/10 §4）。真实 ID 一律不入库。

### 4.5 开放数据域（好友榜，可选）

当前实现：开放数据域代码 `assets/openDataContext/index.js`（入口，收到 `render/hide` 消息后读取 `wx.getFriendCloudStorage` 并绘制到 sharedCanvas）+ 主域桥 `WechatFriendRank`。排行榜面板尚未接入共享画布，微信下「好友」页签降级为世界榜（报告说明）；`WechatCloudService.getLeaderboard({board:'friends'})` 会请求 `global` 保证页签可用。

主域提交成绩时写入托管数据（`bestScore`）的调用点已在 GameRoot 装配层接好（监听 `run.settled` → `platform.setUserCloudStorage`）；`setUserCloudStorage` 由适配器实现（Local 为日志模拟）。

构建后处理（每次构建 wechatgame 后执行一次）：

```bash
npm run wechat:opendata     # 复制 assets/openDataContext → build/wechatgame/openDataContext，并写 game.json 的 openDataContext 字段
```

> Cocos Creator 3.8 构建面板中的「小游戏开放数据域工程（buildSub）」是「把整个工程作为独立开放数据域工程」的另一条路线；本工程采用微信原生目录规范（开放域目录 + index.js 入口 + game.json 字段），两者不要混用。
> 后续把好友榜画到界面：主域用引擎内置 `SubContextView`（或手动把 `openDataContext.canvas` 绘制到场景）；sharedCanvas 宽高只能在主域设置，改尺寸后需再次 postMessage 触发重绘。

## 5. 常用命令

```bash
npm install            # 安装 devDependencies（typescript/vitest/@cocos/creator-types）
npm run check          # 类型检查(core+cc) + 全部单测（提交前必须通过）
npm test               # 仅单测
npm run test:watch     # 监听模式
npm run typecheck:core # core（无 cc）类型检查
npm run typecheck:cc   # ui（含 cc）类型检查
```

> 注意：CLI 类型检查不依赖编辑器；`tsconfig.json` 供编辑器使用（首次打开后 `temp/tsconfig.cocos.json` 才存在）。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| Dashboard 无法识别工程 | 按第 2 节兜底流程补齐 `settings/` |
| 编辑器脚本报 `Cannot find module 'cc'` | 正常，编辑器内部解析；CLI 用 `typecheck:cc` |
| 资源 404 / 界面无色块 | 素材未放入时属于预期占位；素材按 docs/04 路径放入后自动生效 |
| 微信工具报”未找到 game.json“ | 构建产物目录错误，应导入 `build/wechatgame` |
| 云函数调用失败 | 检查 cloudEnvId、云开发环境与函数是否部署；开发期会自动降级本地 |
| Dashboard 安装包下载 403 | 官方 `/CocosDashboard/` 路径对部分网络返回 403（国内直连与普通分流均可能触发）；可挂全局代理下载，并用 winget 清单中的官方 SHA256 校验；Creator 编辑器下载不受影响 |
