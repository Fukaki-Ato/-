# 03 核心服务与事件协议

> 类型与接口签名的唯一事实来源是 `assets/scripts/core/contracts.ts`。本文件描述行为约定、失败原因与关键时序。

## 1. 服务总览

| 服务 | 职责 | 依赖 | 主要触发事件 |
| --- | --- | --- | --- |
| ConfigService | 加载与校核全部配置表，提供查询 | IConfigSource | - |
| CurrencyService | 金币/钻石的读写、消费校验 | save, events | currency.changed |
| InventoryService | 道具增删查、使用 | save, events | inventory.changed, currency.changed |
| RewardService | 结构化奖励发放与描述（货币+道具+角色） | currency, inventory, character | 上述服务对应事件 |
| ShopService | 商品列表（含限购/可购状态）、购买、广告免费领取 | save, clock, config, reward, currency | shop.changed 等 |
| CharacterService | 解锁/升级/选择/属性计算 | save, config, currency, reward | character.changed |
| TaskService | 进度累加、领取、每日/每周重置 | save, clock, config, reward | task.changed |
| AchievementService | 成就进度与领取 | save, config, reward | achievement.changed |
| WelfareService | 签到周期、每日免费广告 | save, clock, config, reward | welfare.changed |
| ActivityService | 活动列表/里程碑/领取/时间窗 | save, clock, config, reward | activity.changed |
| RedDotService | 聚合各服务红点状态 | 全部服务 | reddot.changed |

**通用返回**：`OpResult { ok: boolean; reason?: string }`；失败原因使用 contracts 中的字符串枚举常量（如 `'insufficient' | 'sold_out' | 'not_found' | 'locked' | 'limit' | 'expired' | 'already_claimed' | 'unsupported'`）。

## 2. 关键流程

### 2.1 启动与跨天

```
Boot: platform.init() → createGameContext(configSource, platform)
  → save = repo.load(); (版本迁移/坏档恢复)
  → config.loadAll() + validate
  → redDot.refresh()
  → platform.login()（微信 openid / 本地游客）
  → welfare/task/activity.refreshIfNeeded()  ← 处理离线跨天
  → open MainMenu
运行时: wx.onShow → context.refreshDaily() → 各服务 refreshIfNeeded() → reddot.refresh()
```

### 2.2 购买商品

```
ShopService.buy(goodsId):
  1) 校验商品存在、未过限购（dailyBought/adClaimed + 游戏日）
  2) price=null 且 viaAd → 返回 needAd=true 由 UI 拉起广告后 claimAd
  3) price.currency=CNY → 返回 needPay={productId,priceFen} 由 UI 调 platform.pay 后 claimPay
  4) 普通商品: currency.spend → reward.grant(gain) → 记录 dailyBought → emit shop.changed
  5) 任一失败返回 reason，不做任何部分扣除
广告商品: claimAd(goodsId) 同样校验限购后直接发放（广告由平台层保证已看完）
支付商品: claimPay(goodsId) 在 PayResult.ok 后调用，校验限购后直接发放
```

### 2.3 任务与成就进度

```
来源: run.finished（TaskService.onRunFinished 汇总 run.count/distance/score.single/coins.total/diamonds.total）
      shop.changed（shop.buy.count）、character.changed（character.upgrade.count）、day.changed（login.days）
TaskService.track(metric, value, {absolute}) → 更新 progress（clamp 到 target）→ emit task.changed
claim(id): 校验 claimable → reward.grant → 记录 claimed → emit task.changed
claimAll(type): 批量领取，返回汇总奖励
```

### 2.4 一局结算（详见 docs/06）

```
MainMenu 点击开始 → gameplay.launch(opts)
  → 返回 GameplayResult → emit run.finished（任务/成就/活动进度立即推进）
  → RunSettlementPanel: Settlement.calculate(result, runConfig) → 展示基础奖励
  → [双倍领取] platform.ad.show('settlement.double') 成功后 grants 差额
  → reward.grant → emit run.settled → 保存 → 返回主界面
```

### 2.5 角色升级

```
upgrade(id): level < maxLevel 且 canAfford(cost) → 扣费 → level+1 → emit character.changed
属性 = baseAttr + growth * (level - 1)，结果按字段取整
```

### 2.6 使用道具（IGameContext.useItem）

```
useItem(id):
  1) inventory.use(id) 消耗 1，返回 effect（无 effect 或不可在菜单使用 → unsupported）
  2) effect.kind = 'grant' → reward.grant(effect.reward, 'item.'+id)
  3) effect.kind = 'runBuff' 且 useTargets 含 'menu' → flags['pendingBuff.'+buffId] += 1（下局生效）
  4) effect.kind = 'unlockCharacter' → character.unlock(effect.id)
进入玩法前：从 flags 取出全部 pendingBuff 作为携带道具（取出时即清空）；launch 失败时原样放回，避免白扣道具
```

## 3. 事件表（GameEventMap 摘要）

| 事件 | 载荷 | 触发时机 |
| --- | --- | --- |
| currency.changed | { gold, diamond, deltaGold, deltaDiamond, reason } | 任何货币变动后 |
| inventory.changed | { changed: ItemStack[] } | 道具增减后 |
| character.changed | { id, reason: unlock/upgrade/select } | 角色状态变更 |
| shop.changed | {} | 购买/领取/重置后 |
| task.changed | { ids? } | 进度或领取状态变化 |
| achievement.changed | { ids? } | 同上 |
| welfare.changed | {} | 签到或每日奖励状态变化 |
| activity.changed | { ids? } | 进度/领取/时间窗变化 |
| reddot.changed | { key, on } | 红点状态翻转（仅翻转时发射） |
| run.started | GameplayLaunchOptions | 进入玩法前 |
| run.finished | GameplayResult | 玩法返回后 |
| run.settled | { result, reward, doubled } | 结算发放完成 |
| day.changed | { date, prevDate } | 游戏日变化 |
| save.loaded | { fresh } | 存档载入完成 |
| toast | { text } | 服务层需要 UI 提示（尽量少用） |

## 4. 一致性与幂等要求

1. **领取类接口幂等**：重复调用已领取的 `claim` 返回 `already_claimed`，不得重复发货。
2. **广告回调**：`claimAd` 必须再次校验限购，防止 UI 重复回调。
3. **负数防护**：`spend/remove` 传入负数或超量直接返回失败。
4. **重置边界**：任何写操作前先执行对应 `refreshIfNeeded()`（或由调用方保证），防止跨天写错周期数据。
5. **顺序**：先校验后扣除再发放；发放中若有子步骤失败（不应发生）以日志告警，不静默。

## 5. 组合根

`core/services/index.ts`（S03 完成）导出：

```ts
export interface CreateContextOptions {
  platform: IPlatformAdapter;
  configSource: IConfigSource;
  now?: number;
  /** v1 Mock 玩法参数（delayMs/random 可注入，供测试）；实现见 services/index.ts */
  gameplay?: MockGameplayOptions;
}

export function createGameContext(opts: CreateContextOptions): Promise<IGameContext>;
```

职责：构造各服务并注入依赖、加载存档与配置、注册事件联动（如 `day.changed` → 各服务 refresh、RedDotService 订阅）、实现 `markDirty/flush/refreshDaily`。创建完成后立即执行一次 `refreshDaily()`（建立 `flags.lastGameDay` 基线并触发首次 `day.changed`，使 `loginDays` 从 1 开始），随后无条件执行一次 `redDot.refresh()`（同日重启不会触发 `day.changed`，红点需在返回前完成首次计算）。
